# Nominal AK4 JEC for 2024 background MC

## Scope and activation

This is the first, deliberately limited JERC implementation for this analysis.
It changes only AK4 PUPPI `Jet_pt` and `Jet_mass`, before analysis region/object
selection, for background MC with `dataset_year == "24"`.
Data, `Signal`, other years, AK8 and generator-only processing are unchanged.

`AK4_JEC_CORR` defaults to **0** in `setup.py` and in the C++ class. For a
controlled validation run, set it to 1 and regenerate the framework configuration
using `python setAnalysis.py -a AP_bbhZDM_Had_R3` from the parent HEPHero directory.
Check that the generated input contains both `AK4_JEC_CORR 1` and `jet_jerc`.
Do not enable it for final MET-sensitive results until Type-1 MET is recomputed.

## Payload and algorithm

- Versioned payload: `Metadata/POG/JME/2024/jet_jerc.json.gz`.
- Source: the user-provided 2024 JSON from
  `/home/mcostare/Desktop/02_Correcoes_e_Calibracoes/JER/jet_jerc.json.gz`.
- Compressed-file SHA-256:
  `b0e60dd2244f9d4cfa3215eafb94afa5b6a491b18af4584522b749d56f5c9540`.
- Compound key: `Summer24Prompt24_V5_MC_L1L2L3Res_AK4PFPuppi`.
- Replaces the previously committed V1 payload. No online `latest` lookup occurs.

For each stored NanoAOD jet:

```text
raw_pt   = Jet_pt   * (1 - Jet_rawFactor)
raw_mass = Jet_mass * (1 - Jet_rawFactor)
JEC = compound(Jet_area, Jet_eta, raw_pt, rho, Jet_phi)
Jet_pt   = raw_pt   * JEC
Jet_mass = raw_mass * JEC
```

The compound evaluator owns the sequential level updates; individual levels must
not be multiplied a second time. All evaluator inputs are doubles. The JEC set is
loaded once in `PreRoutines`, and `ApplyAK4JEC` is called once from `RunRoutines`,
after input `GetEntry` and before `AnaRegion`. It is not called inside
`JetSelection`, which can be called repeatedly by selections.

`Jet_area` and `Jet_rawFactor` are bound only when the correction is active.
The rho branch is `Rho_fixedGridRhoFastjetAll`, with an explicit fallback to
`fixedGridRhoFastjetAll`. Missing/incompatible inputs, invalid numeric values,
missing files and absent payload keys fail rather than silently returning unity.
`Jet_rawFactor` retains its input meaning and is not a second correction to apply
to the already updated jet. Input branches are reloaded for the next event.

## Tests

From this analysis repository, with the normal HEPHero compiler/include environment:

```bash
python3 tests/run_ak4_jec_tests.py
```

On the inspected UERJ host, the vendored correction evaluator additionally needs
the existing LCG xxhash headers. The standalone test was run with:

```bash
CPLUS_INCLUDE_PATH=/cvmfs/sft.cern.ch/lcg/views/LCG_105/x86_64-el9-gcc11-opt/include \
  python3 tests/run_ak4_jec_tests.py
```

Tests compile and execute the C++ evaluator against the real compressed V5 JSON,
compare pt/mass and raw-factor handling with a direct compound evaluation at signed
eta values, verify scope/disable behavior, numeric rejection and missing-file
errors, and validate the actual setup dictionaries. Tests do not replace the
physics validation of distributions and yields.

An optional `AK4_JEC_JET_SAMPLE` environment variable accepts whitespace-separated
rows `pt mass rawFactor eta phi area rho` extracted from an existing ROOT input.

## Explicitly not included

- JER smearing or JES/JER up/down variations.
- AK8 energy or mass corrections.
- Type-1 PUPPI MET recomputation/propagation.
- JSON-based Jet ID and jet veto maps.
- Changes to pileup, b tagging, signals or the enclosing HEPHero repository.

A production 2024 input was attempted through XRootD, but access requested grid
proxy authentication. No credentials were requested or supplied. A production
2024 end-to-end physics validation remains to be performed with authorized input
access. Existing fixed-size jet arrays are a framework limitation; this change
does not redesign the input reader.
